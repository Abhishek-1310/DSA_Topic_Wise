how we need 1d arr instead of one metrix

Imagine the matrix:

ROW 0 → [ A B C D ]
             ↓
ROW 1 → [ E F G H ]
             ↓
ROW 2 → [ I J K L ]

We don't store:
[A B C D]
[E F G H]
[I J K L]
We only keep:
[A B C D]
then overwrite it:
[E F G H]
then overwrite it:
[I J K L]

So:
2D DP:
[A B C D]
[E F G H]
[I J K L]

1D DP:
[A B C D]
     ↓
[E F G H]
     ↓
[I J K L]

That's what space optimization means.

how to choose outter an dinner loop

Simple rule
Ask yourself: "What am I processing one by one?"

1. If each amount/state is the thing you're building → amount outer
Example: Coin Change (minimum coins)

for (let amount = 1; amount <= target; amount++) {
    for (let coin of coins) {
        ...
    }
}
Because:
For each amount, try every coin.
amount → try choices

2. If each item/number must be used only once → array outer
Example: Target Sum / Count Subsets

for (let num of nums) {
    for (let sum = target; sum >= num; sum--) {
        ...
    }
}

Because:
Process each number once, then update possible sums.

item → update states
The cheat rule 🧠
COUNT / SELECT items (0/1)
        ↓
items outer
sum    inner BACKWARD
BUILD minimum/maximum amount
        ↓
amount outer
items  inner

But the more fundamental rule is:
If an item can be used only once → process item once and move sum backward.
If an item can be reused → sum can move forward.
